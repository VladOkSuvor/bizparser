# bizparser

Сбор контактов малого бизнеса из открытых источников. По умолчанию — полностью
бесплатный стек: **OpenStreetMap (Overpass + Nominatim)** для discovery,
**сайты самих бизнесов** для обогащения контактов. Ни одного API-ключа, ни
одного биллинга. Есть опциональный платный шаг (Google Places, выключен без
ключа) — им точечно добираются лиды, которым не хватило данных.

Цель — получить список мест, которым можно предложить свои услуги, с телефоном/почтой/соцсетями
и грубой оценкой размера.

Основная вертикаль — **частная медицина по всей Украине**: стоматологии, клиники,
кабинеты, лаборатории, реабилитация. Помимо OSM для неё подключены открытые данные
НСЗУ (с ФИО руководителя — ЛПР) и мед-агрегаторы likarni.com и doc.ua. Лидам без
сайта вместе с ботом предлагаем сайт — для них есть отдельный список.

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # и впиши свой контакт в USER_AGENT
```

`USER_AGENT` — не формальность. Nominatim и Overpass требуют идентифицируемый
User-Agent с контактом; безликие клиенты банят. Шаблонный `you@example.com`
Nominatim отбивает сразу (403) — геокодинг тогда молча не работает.

## Быстрый старт

```bash
# что вообще можно искать
python -m bizparser categories

# найти все салоны красоты, тату и спа в Киеве
python -m bizparser discover --city "Київ" --category beauty_all

# зайти на их сайты и вытащить телефоны/почты/соцсети
python -m bizparser enrich --limit 100

# посмотреть, что получилось
python -m bizparser stats
python -m bizparser list --with-contact

# выгрузить в CSV для обзвона
python -m bizparser export -o leads.csv
```

Категорий можно указывать несколько: `-k hairdresser -k dentist -k cafe`.
Есть бандлы (`beauty_all`, `medical`, `horeca`, `services`) и `all`.

### Мед по всей Украине

```bash
# план: какие города и категории, что уже пройдено — без запросов
python -m bizparser discover-all --dry-run

# частная медицина по всем областным центрам и крупным городам
python -m bizparser discover-all

# госреестр НСЗУ: частные клиники и ФОП-врачи с телефоном, email и руководителем
python -m bizparser import-nszu

# мед-агрегаторы: телефоны клиник с likarni.com, отметка «записывает через doc.ua»
python -m bizparser import-likarni --only "Львів,Ужгород"
python -m bizparser import-docua --only "Львів"

# сайты и автоматизация — как обычно
python -m bizparser enrich --limit 200

# апсейл: у кого нет сайта — звоним с предложением «сайт + бот»
python -m bizparser list --no-website --category dentist
python -m bizparser export --no-website -o no_website.csv
```

## Как это устроено

### 1. Discovery — Overpass API

Nominatim превращает `"Київ"` в area ID (`3600421866`), Overpass ищет по нему POI
по тегам категории. Запрос строится через `nwr` (node + way + relation) — салон
может быть и точкой, и контуром здания.

```
[out:json][timeout:180];
area(3600421866)->.searchArea;
(
  nwr["shop"="hairdresser"](area.searchArea);
);
out center tags;

```

Многие места уже содержат `phone`, `website`, `contact:*` прямо в ответе — без
дополнительных запросов. Посмотреть сгенерированный запрос, ничего не выполняя:
`discover ... --dry-run`.

**Честный минус:** покрытие телефонов/сайтов у малого бизнеса в OSM заметно хуже,
чем в Google Maps — не все владельцы туда что-то добавляют. На реальном прогоне
(тату-студии Киева) из OSM пришло ~50% с телефоном и ~50% с сайтом. Дальше добираем
enrichment'ом.

**Отсечка крупных сетей.** Супермаркеты, гипермаркеты и DIY-магазины (Сільпо,
Епіцентр и т.п.) в холодной рассылке бесполезны — решение об автоматизации там
принимает не человек за прилавком. `discover` отсеивает их прямо на этапе
разбора Overpass-ответа: по формату торговли (`shop=supermarket`, `doityourself`,
`mall`…) и резервно по списку известных брендов в [`chains.py`](bizparser/chains.py),
на случай если сеть затесалась под безобидным тегом вроде `shop=convenience`.
Число пропущенных сетей видно в логе. Если нужно всё-таки собрать и их —
`discover ... --include-chains`.

### 1a. Вся Украина — `discover-all`

`discover` гоняет один город. `discover-all` идёт по списку
[`bizparser/data/cities_ua.json`](bizparser/data/cities_ua.json): все областные
центры + крупные города (~75 штук), от больших к малым. Сёла и посёлки не берём:
для холодных B2B-продаж там либо ФАП, либо ничего.

- **По городам, а не одним запросом на страну.** Запрос по площади всей Украины —
  огромный ответ, таймаут и риск бана бесплатного инстанса. Между городами —
  пауза `CITY_DELAY` (30 с) поверх обычной паузы между запросами Overpass.
- **Мед первым.** Категории бандла `medical` всегда идут в начале каждого города,
  остальное (`-k horeca` и т.п.) — после. По умолчанию гоняется только `medical`.
- **Area ID кэшируется** в таблице `city_areas`: Nominatim спрашивается один раз на
  город за всю жизнь базы (обычный `discover` тоже пользуется этим кэшем).
- **Продолжение после сбоя.** Пара «город + категория» отмечается в `scrape_runs`
  только при успешном ответе Overpass. Упал на 15-м городе с 504 — запусти ту же
  команду ещё раз: пройденное пропустится, догонятся только остальные. После трёх
  сбоев подряд (`--max-failures`) команда сама останавливается — Overpass лежит,
  долбить его бессмысленно. `--force` — пройти всё заново.
- **Оккупированные и прифронтовые города исключены по умолчанию** (Донецьк,
  Маріуполь, Херсон, Нікополь, Краматорськ…) — туда некому и неудобно звонить.
  Причина записана в поле `excluded`. Ситуация меняется: включить город точечно —
  `--only "Херсон"`, все сразу — `--include-excluded`. Правь JSON, когда нужно.

Полезные ключи: `--top 10` (только 10 крупнейших), `--only "Львів,Луцьк"`,
`--with-pharmacy` (аптеки — другая экономика и ЛПР, поэтому только явно),
`--cities my.json` (свой список в том же формате).

### 1b. Мед-вертикаль: кого берём, кого отсекаем

Бандл `medical`: `dentist`, `clinic`, `doctors` (частные кабинеты — гинеколог,
педиатр, семейный врач), `lab`, `rehab`, `cosmetology` (как мед. услуга,
`healthcare:speciality`), `hospital`. `vet` и `pharmacy` — отдельными категориями.

Цель — частники, где на том конце провода владелец или директор. Поэтому на
discovery отсекаются:

- **государственные и коммунальные** ([`publicsector.py`](bizparser/publicsector.py)) —
  там ЛПР не собственник, а бюджет и тендер. Признаки: `operator:type=public`,
  «КНП», «комунальн», «ЦПМСД», «міська поліклініка», «обласна лікарня»,
  «№» в названии поликлиники/больницы, НИИ и т.п. Больница (`amenity=hospital`)
  без признака частной считается государственной. Вернуть — `--include-public`;
- **мед-сети** ([`chains.py`](bizparser/chains.py)): лаборатории (Synevo, Діла,
  Ескулаб, CSD…), аптечные сети, крупные сети клиник (Добробут, Into-Sana,
  Medicover…). Проверка по первым словам названия, только у медицины.

### 1c. Источники, помимо OSM (мед)

Общего ключа с OSM у них нет, поэтому сопоставление ([`sources/base.py`](bizparser/sources/base.py)):
телефон в том же городе → название + адрес (номер дома и улица) или координаты
в радиусе 150 м → название, если такое в городе одно (у сетевых филиалов-тёзок
не угадываем). Совпало — дозаполняются только пустые поля, собранное раньше не
затирается. Не совпало — новый лид с `osm_id` вида `nszu/<id>`. Повторный импорт
ничего не дублирует.

**НСЗУ (`import-nszu`)** — вместо реестра лицензий МОЗ из первоначального плана.
У МОЗ реестр машиночитаемо не выгружается: среди наборов министерства на
data.gov.ua его нет, а moz.gov.ua закрыт Cloudflare-челленджем. Зато Национальная
служба здоровья публикует на data.gov.ua ежедневно обновляемые CSV о всех, кто
работает по программе медгарантий: форма собственности, ЄДРПОУ, телефон, email,
сайт и **руководитель** — готовое имя ЛПР для звонка. Берём только `ФОП` и
`Приватна`, без ФАПов, без сетей от 10 подразделений, только города из списка
(`--all-settlements` — все). Около 1 750 точек, у всех есть телефон.
Ограничение: здесь только те, у кого договор с НСЗУ — в основном первичка
(семейные врачи) и часть специализированной помощи. Частная стоматология без
договора сюда не попадёт — её даёт OSM. У ФОП в поле ЄДРПОУ лежит личный
налоговый номер — его не сохраняем.

**likarni.com (`import-likarni`)** — вместо DDG-поиска по агрегатору. Их внутренний
поиск закрыт в robots.txt (`*/search*`), поэтому идём по открытым листингам
города (`/kliniki/<город>/page/N`) и берём schema.org JSON-LD из карточки:
название, телефон, email, адрес. Нюанс: у части клиник вместо их номера стоит
подменный номер колл-центра likarni — номер, встретившийся на 3+ карточках,
отбрасывается. Slug города на likarni есть у 25 крупных городов. Пауза 3 с,
Київ — это сотни карточек, т.е. десятки минут.

**doc.ua (`import-docua`)** — телефонов клиник doc.ua не отдаёт вообще: на карточке
только их колл-центр (337-07-07), `/api/` закрыт в robots.txt. Поэтому модуль
только **помечает** уже собранные лиды `automation.listing = doc.ua`: клиника
принимает запись через агрегатор и платит ему — хороший заход для питча своего
бота. Это слабый сигнал: лид не становится «автоматизированным» и из горячих не
выпадает. Карточки берутся из открытого sitemap. `--add-new` — заводить и
несовпавшие клиники (без телефона, дальше их добирают `find-sites`/`google-places`).

Отдельных врачей с likarni/doc.ua (потенциальные лиды для персонального бота)
пока не собираем — карточки врачей не содержат прямых контактов.

### 2. Enrichment — сайты самих бизнесов

Если есть `website`, но нет телефона/почты — заходим на сайт: главная плюс до трёх
страниц вида `/contact`, `/contacts`, `/about` того же домена. Оттуда:

- телефоны — из `tel:` ссылок и из видимого текста через `phonenumbers`
  (не regex-простыня: библиотека валидирует номер и нормализует в E.164);
- почта — из `mailto:` и из текста, с фильтром шаблонного мусора
  (`example.com`, `noreply@`, `something@2x.png`);
- соцсети — Instagram / Facebook / Telegram / TikTok / Viber / WhatsApp из футера.
  Для украинского малого бизнеса соцсети часто важнее сайта, поэтому они
  отдельными колонками в экспорте.

`robots.txt` уважается по умолчанию (`RESPECT_ROBOTS=0` отключает). Между
запросами — пауза.

### 3. Fallback — поиск сайта через DuckDuckGo

Для мест, у которых в OSM вообще нет сайта:

```bash
python -m bizparser find-sites --limit 10 --category dentist
```

**Читай, прежде чем запускать.** HTML-выдача DuckDuckGo не требует ключа и публично
доступна, но её автоматический разбор — серая зона по их ToS, и при частых запросах
прилетает бан по IP. Поэтому: спрашивает подтверждение, пауза 6 секунд между
запросами, лимит по умолчанию 10. Это инструмент для узкого списка «перспективных»
мест, а не основной канал discovery. Агрегаторы (OLX, 2GIS, Zoon, work.ua…)
отфильтровываются — нужен сайт самого бизнеса.

По умолчанию ищет только у тех, у кого нет ни сайта, ни телефона. Для апсейл-списка
«нет сайта» полезно проверить и лиды с телефоном — `--with-phone`. Сбой DDG (нет
ответа, капча) не записывается как «сайта нет»: такие места получают
`website_status=ddg_failed` и ищутся снова при следующем запуске. Три отказа
подряд без единой находки — прогон останавливается (похоже на бан).

### 3a. Апсейл: сайт вместе с ботом

Если после OSM, enrichment и DDG сайта так и нет — это не «лид без данных», а
отдельный сегмент: предложить заодно сайт-одностраничник. Состояние в колонке
`website_status`:

| значение | когда ставится |
|---|---|
| `has_website` | сайт есть (из OSM, НСЗУ, найден DDG — ставится автоматически) |
| `not_found` | DDG-выдача пришла, сайта в ней нет |
| `site_down` | сайт в базе есть, но не открывается (`enrich`: unreachable/bad_url) |
| `ddg_failed` | поиск не прошёл — повторится |
| пусто | сайта нет, но и не искали |

`list --no-website` / `export --no-website` — всё, кроме `has_website`, только с
контактом; в списке видно состояние и ЛПР. «Не искали» тоже попадает в список
(иначе он пуст до первого `find-sites`), но перед обзвоном лучше прогнать
`find-sites --with-phone` — чтобы не предлагать сайт тому, у кого он есть.
Сводка по сегменту — в `stats`. Скрипт для звонарей — [`docs/call_script_no_website.md`](docs/call_script_no_website.md).

### 4. Опционально — Google Places (New), платно

Единственный платный шаг во всём пайплайне, и он выключен по умолчанию —
без `GOOGLE_PLACES_API_KEY` в `.env` команда сама откажется работать:

```bash
python -m bizparser google-places --dry-run   # кого бы взяли, без вызовов
python -m bizparser google-places --limit 30  # дозаполнить телефон/адрес
```

Дёргает не всех подряд, а только тех, кому реально не хватает данных, — гейт
в `needs_lookup()` (`bizparser/google_places.py`):

- сайт уже проверен enrichment'ом, но телефона так и не нашлось;
- лид «горячий» (нет автоматизации + уже есть хоть какой-то контакт) — то же
  определение, что в `stats`/`list --no-automation`.

На каждый лид — до двух вызовов: сначала `Text Search` с field mask `places.id`
(самый дешёвый SKU), `place_id` кэшируется в БД навсегда, повторно не ищем;
затем `Place Details` по этому id за именем/адресом/телефоном/часами работы.
**Тарифная ловушка**: `phoneNumber` и `openingHours` сами по себе уже переводят
запрос в SKU Enterprise (~$35/1000), а не Pro (~$32/1000) — Pro покрывает только
имя/адрес/координаты. Раз телефон и часы всё равно требуют Enterprise, `rating`
и `reviews` в field mask не добавлены: они не нужны для лидогена, а `reviews`
вдобавок утянул бы на `Enterprise + Atmosphere` (дороже всех). Актуальные
тарифы смотри в Google Cloud Console — Google их пересматривает.

Свой бюджетный потолок (таблица `api_usage`, счётчик вызовов по месяцам) —
поверх квоты в облаке, а не вместо неё: `--limit` дополнительно режется
остатком месячного бюджета, если он меньше. Раз проверенный лид
(`google_checked_at` проставлен) повторно не трогается без `--recheck`, даже
если Details ничего не нашли.

### 5. Опционально — Google Sheets, общий вид для команды

Бесплатно (в отличие от Places — Sheets API не тарифицируется по вызовам).
Коворкеры видят и правят статус лида прямо в таблице, без доступа к базе:

```bash
python -m bizparser sheets-sync
```

**Настройка (один раз):**

1. [Google Cloud Console](https://console.cloud.google.com) → создать проект →
   включить **Google Sheets API** и **Google Drive API**.
2. Там же → *APIs & Services → Credentials → Create Credentials → Service
   Account*. Создать, зайти в неё → *Keys → Add Key → JSON* — скачается файл.
   Положить его в корень проекта как `service_account.json` (или указать путь
   в `GOOGLE_SERVICE_ACCOUNT_FILE`). **В git не коммитить** — уже в `.gitignore`.
3. Создать пустую Google-таблицу вручную, открыть **Share** и дать доступ
   *Editor* тому e-mail, что указан в JSON-ключе как `client_email`
   (`...@...iam.gserviceaccount.com`) — без этого шага сервис-аккаунт таблицу
   не увидит, хотя ключ будет валидным.
4. ID таблицы — из её URL: `docs.google.com/spreadsheets/d/`**`ЭТОТ_ID`**`/edit`.
   Вписать в `.env` как `GOOGLE_SHEETS_ID`.

**Как это работает.** Не два независимых направления, а один порядок,
всегда один и тот же: сначала `pull` — переносит из таблицы в БД только
колонки `status` и `notes` (это «территория» коворкеров), потом `push` —
полностью перезаписывает таблицу свежим снимком из БД. pull всегда раньше
push, поэтому свежий снимок не затирает то, что кто-то успел вписать между
прогонами. Лист называется `Leads`, создаётся сам при первом запуске.

**Важно понимать:** если коворкер поправит в таблице не `status`/`notes`, а,
скажем, телефон — правка тихо исчезнет при следующем `sheets-sync`: телефон
всегда приходит из БД. Это осознанное разделение, а не баг — источник правды
для данных один (БД + discovery/enrichment), таблица — только окно и
workflow-поле для команды. Многострочные заметки (`set-status --note`
копит их через перенос строки) в таблице схлопнутся в одну строку — так же,
как в CSV/JSON-экспорте.

Синхронизация не realtime — гоняй `sheets-sync` вручную, когда нужно (после
`discover`/`enrich`, или просто по расписанию себе на память).

## Оценка размера бизнеса

`size_estimate` (`micro` / `small` / `medium`) — **эвристика, а не факт**. OSM не
хранит ни выручку, ни штат. Считается из косвенных сигналов: базовый вес по типу
заведения, число точек с тем же названием (сетевик или нет), теги `brand`/`operator`,
наличие сайта и почты, `capacity`/`rooms`/`beds`, `opening_hours=24/7`. Все сработавшие
сигналы пишутся в поле `size_signals` — видно, на чём основана оценка.
`confidence` там всегда `low`, и это честно.

### ЄДР — что стоит подключить дальше

Для Украины есть источник получше review_count: **Єдиний державний реєстр** публикуется
как открытые данные на [data.gov.ua](https://data.gov.ua) — скачивается целиком одним
файлом, бесплатно, без лимитов на запросы (это файл, а не API). Оттуда: КВЕД (код
деятельности) и статус регистрации — не даёт employee count напрямую, но позволяет
отличить живого действующего ФОПа от мёртвой регистрации и сверить название/адрес.

Это не реализовано: структура выгрузки специфичная, и разбираться в ней надо отдельно,
когда дойдут руки. Для лидов из НСЗУ ЄДРПОУ уже лежит в колонке `edrpou` — по нему
ЄДР матчится точно; остальным — по нормализованному названию + улице.

**Opendatabot** как публичный API для массовой проверки не подойдёт — у них бесплатно
порядка 5 проверок в день для физлиц, для объёма это не вариант.

## Схема БД

SQLite по умолчанию (`businesses.db`), схема совместима с Postgres — поменяй `DB_URL`.

| поле | что внутри |
|---|---|
| `osm_id` | `node/7542356385`, уникален; по нему идёт дедупликация. У записей не из OSM — `nszu/<id>`, `likarni/<slug>` |
| `name`, `category`, `city`, `address`, `lat`, `lon` | из OSM |
| `phone` | нормализован в E.164 (`+380671234567`) |
| `email`, `website`, `socials` | socials — JSON `{"instagram": "...", "telegram": "..."}` |
| `size_estimate`, `size_signals` | эвристика и её обоснование |
| `source` | `osm` / `osm,website_scrape` / `osm,nszu,likarni` … — накапливается |
| `status` | `new` → `enriched` → `contacted` → `replied`/`rejected`, плюс `no_contacts` |
| `raw_tags` | все теги OSM целиком — чтобы не перезапрашивать, если понадобится ещё поле |
| `notes` | доп. телефоны, причины отказов (`[site:robots_disallow]`, `[ddg:none]`) |
| `website_status` | `has_website` / `not_found` / `site_down` / `ddg_failed` — см. «Апсейл» |
| `contact_person`, `edrpou` | руководитель (ЛПР) и ЄДРПОУ юрлица — из НСЗУ |
| `external_ids` | связь с внешними источниками: `{"nszu": "<division_id>", "likarni": "<slug>"}` |
| `google_place_id`, `google_places_data`, `google_checked_at` | кэш опционального Google Places (см. выше); `google_checked_at` — маркер «уже смотрели», защищает от повторных платных вызовов |

Повторный `discover` по тому же городу не создаёт дублей и **не затирает** результаты
enrichment'а: у существующих записей дозаполняются только пустые поля.

Отметить результат работы с лидом:

```bash
python -m bizparser set-status 42 contacted --note "написал в телеграм 12.08"
```

## Rate limits

Троттлинг вшит в HTTP-клиент, а не оставлен на дисциплину вызывающего кода —
пауза выдерживается по каждому хосту отдельно, плюс экспоненциальный backoff на
429/503/504. Дефолты (секунды между запросами):

| сервис | пауза |
|---|---|
| Nominatim | 1.2 (их policy — не чаще 1 req/sec, жёстко) |
| Overpass | 3.0 |
| сайты бизнесов | 1.0 |
| DuckDuckGo | 6.0 |
| likarni.com, doc.ua | 3.0 |
| между городами в `discover-all` | 30 |

Уменьшать — плохая идея: публичные инстансы Overpass и Nominatim живут на
пожертвованиях, и единственная причина, по которой они не требуют ключ, — что их
не долбят. Если нужен реально большой объём — поднимай свой инстанс Overpass
(docker-образ `wiktorn/overpass-api`), для старта хватит публичного. Зеркала на
случай перегруза основного — в `.env.example`.

## Правовая сторона

Данные OSM — под ODbL, использовать можно, при публикации производных данных нужна
атрибуция «© OpenStreetMap contributors». Контакты бизнесов — это данные юрлиц и ФОП,
опубликованные ими самими; для холодных писем в ЕС/Украине смотри требования по
маркетинговым рассылкам (законная цель, возможность отписаться). Инструмент собирает
то, что бизнес сам выложил в открытый доступ, — что дальше с этим делать, решаешь ты.
